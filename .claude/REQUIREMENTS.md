# 기능 요구사항 (Functional Requirements)

> 스마트글래스 시뮬레이션. 데모 여행지는 **서울** 고정.
> 이 문서는 [ARCH.md](ARCH.md)의 기능 정의를 "무엇을 만들어야 하는가" 기준으로 구체화한 것.
> 각 요구사항은 `FR-<기능>-<번호>`로 식별한다. 우선순위: **필수**(데모 필수) / **고도화**(여유 시).

---

## 0. 공통 / 시스템 요구사항

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-SYS-1 | 웹페이지에서 웹캠(`getUserMedia`) 화면을 실시간 표시한다. | 필수 |
| FR-SYS-2 | 웹캠 화면 위에 정보 오버레이(자막·경로·환율·알림)를 얹는다. | 필수 |
| FR-SYS-3 | 현재 어떤 기능이 실행 중인지(번역/길찾기/환율/질문응답) UI 상태로 관리하고, 한 번에 하나의 주 기능만 활성화한다. | 필수 |
| FR-SYS-4 | 각 기능은 웹페이지 버튼으로 on/off 트리거한다. | 필수 |
| FR-SYS-5 | 모든 REST 응답은 공통 포맷 `{status, msg, data}`(BaseResponse)를 따른다. | 필수 |
| FR-SYS-6 | 기능 실패 시 서버·클라이언트가 중단되지 않고 `status`/`msg`로 원인을 표시한다. | 필수 |
| FR-SYS-7 | 여러 모듈(STT→LLM→map 등)을 거치는 기능은 서버가 조립(orchestration)한다. | 필수 |

## 1. 실시간 대화 번역 (F-STT)  — 담당: 지유찬

CLOVA Speech 스트리밍 인식으로 상대방 발화를 실시간 번역해 자막으로 띄운다.

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-STT-1 | 버튼 클릭 시 사용자 컴퓨터 마이크 입력을 받아 스트리밍을 시작한다. | 필수 |
| FR-STT-2 | CLOVA Speech 스트리밍 API(gRPC)로 실시간 인식·번역한다. | 필수 |
| FR-STT-3 | 번역 언어는 사용자가 웹에서 설정한 값을 사용한다. | 필수 |
| FR-STT-4 | N초 단위로 자막을 갱신하며 화면에 표시한다. | 필수 |
| FR-STT-5 | 버튼 재클릭 시 스트리밍을 중단한다. | 필수 |
| FR-STT-6 | 대화 맥락에 맞는 예상 답변 N개를 함께 제시한다. | 고도화 |

- **통신:** CLOVA Speech 연동은 gRPC 스트리밍, 웹↔서버는 WebSocket (N초 갱신)
- **언어 설정:** 웹 설정값(언어쌍)을 스트리밍 시작 시 서버로 전달
- **미확정:** N값

## 2. 이미지 번역 (F-IMG)  — 담당: 미정

CLOVA Papago imgToimg로 웹캠에 잡힌 텍스트(간판·메뉴판 등)를 번역한다.

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-IMG-1 | 버튼 클릭 시 TTS로 "움직이지 마세요" 음성을 출력한다. | 필수 |
| FR-IMG-2 | 웹캠 화면을 캡처해 Papago imgToimg API를 호출한다. | 필수 |
| FR-IMG-3 | 버튼 재클릭 전까지 웹캠 화면을 번역된 이미지로 대체 표시한다. | 필수 |
| FR-IMG-4 | 사용자가 움직여도 실시간으로 이미지 번역을 갱신한다. | 고도화 |

- **통신:** REST (캡처 1장 → 번역 이미지 1장)
- **미확정:** 실시간 이미지 번역 구현 가능 여부

## 3. 길찾기 (F-MAP)  — 담당: 윤태준 · (STT 지유찬 · LLM 박찬영)

음성 명령에서 목적지를 추출해 네이버 지도 경로를 오버레이한다.

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-MAP-1 | 버튼 클릭 시 STT로 사용자 음성 명령을 텍스트로 변환한다. | 필수 |
| FR-MAP-2 | 명령 텍스트를 LLM에 입력해 목적지(상호명/주소)를 추출한다. | 필수 |
| FR-MAP-3 | 목적지를 좌표로 변환한다. 상호명이면 지역검색 후 실패 시 도로명 주소로 폴백한다. | 필수 ✅ |
| FR-MAP-4 | 출발지(도로명 주소)와 목적지 좌표로 네이버 지도 경로를 계산한다. | 필수 ✅ |
| FR-MAP-5 | 경로·예상 시간·거리 등을 사용자 화면에 오버레이한다. | 필수 |
| FR-MAP-6 | 목적지/경로를 못 찾으면 `status`/`msg`로 사유를 반환한다. | 필수 ✅ |

- **통신:** REST (서버 조립: STT → LLM → map)
- **구현 상태:** `modules/map`의 `geocode`/`search_place`/`get_directions` 완료. STT·LLM 연동 및 오버레이 미구현.

## 4. 질문 응답 (F-QA)  — 담당: 박찬영 · (STT 지유찬)

음성 질문을 LLM/RAG로 추론해 답변을 음성·영상으로 출력한다.

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-QA-1 | 버튼 클릭 시 STT로 사용자 질문을 텍스트로 변환한다. | 필수 |
| FR-QA-2 | 질문을 LLM(+RAG)에 입력해 답변을 생성한다. | 필수 |
| FR-QA-3 | 답변을 TTS 음성 + 화면 오버레이로 출력한다. | 필수 |

- **통신:** REST (서버 조립: STT → LLM/RAG)
- **미확정:** RAG 지식 베이스 범위(서울 여행 정보?)

## 5. 환율 변환 (F-EXC)  — 담당: 박찬영 · 윤태준

메뉴판 등의 가격을 인식해 사용자 통화로 환산한다.

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| FR-EXC-1 | 사용자 음성(STT)으로 환율 변환을 트리거한다. | 필수 |
| FR-EXC-2 | OCR로 화면의 가격·통화 정보를 추출한다. | 필수 |
| FR-EXC-3 | 추출 정보를 LLM에 입력해 메뉴/가격을 정리하고 환산한다. | 필수 |
| FR-EXC-4 | 환산 결과를 화면에 오버레이한다. | 필수 |

- **통신:** REST (서버 조립: STT/OCR → LLM)
- **미확정:** 환율 데이터 출처(고정값 vs 실시간 API), OCR 엔진

## 확정 필요 이슈 (초반 합의 대상)

1. **모듈 간 인터페이스(입출력 스키마)** — 서버 조립이라 STT→LLM→map 사이 데이터 형식을 담당자끼리 먼저 고정.
2. **LLM/RAG 호출 방식** — 서버가 `/llm`·`/rag`를 import(같은 프로세스) vs HTTP 호출(별도 서비스). → HTTP 권장.
3. **STT/알림 WebSocket 메시지 포맷.**
4. **환율 데이터 출처**, **번역 언어쌍/N값**, **OCR 엔진**.
